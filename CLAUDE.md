# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Bun workspace (`apps/*`) plus a Cargo workspace (`crates/sush-core`, `apps/desktop/src-tauri`).

```sh
bun install
bun run dev              # auth server + Ollama + desktop app together
bun run dev:app          # desktop app only (tauri dev, Vite on fixed port 1420)
bun run dev:server       # auth server only, http://localhost:3000
bun run typecheck        # tsc in every workspace
bun --filter desktop build   # tsc + vite build (CI runs this)
bun run build            # compile auth sidecar + release installers

cargo test --workspace                       # what CI runs (Linux/Windows/macOS)
cargo test -p sush-core                      # core only
cargo test -p sush-core <name_substring>     # single test
cargo run -p sush-core --example chat -- <openai|anthropic> <base_url> <model> "prompt"   # SUSH_API_KEY for the key
```

There are no JS tests or linter configured; `typecheck` is the TS gate. Rust tests are inline `#[cfg(test)]` modules (decoders are tested against recorded SSE streams).

Building the Tauri crate needs CMake + libclang (whisper.cpp via `whisper-rs`). On Windows, set `CMAKE` / `LIBCLANG_PATH` if they aren't on PATH (see README).

Releases: push a `v*` tag matching the version in `tauri.conf.json`; `.github/workflows/release.yml` builds every platform.

## Architecture

Three parts:

- **`crates/sush-core`**: pure Rust, no Tauri dependency (keep it that way; it is meant to back a future CLI/TUI too). Holds the message model (`message.rs`: `Message`, `Part`, `ChatEvent`, `ChatRequest`), the `Provider` trait, SSE parsing, MCP client (`mcp/`: stdio + HTTP transports and OAuth), remote transcription, local persistence (`store.rs`, `memory.rs`), the agent loop (`agent/`), and Cowork workspaces (`workspace/`).
  - `agent/run.rs`: one run on a thread: stream a model step, resolve its tool calls (`Approval::Auto` ones run, `Ask` ones wait for the user, so the run reports `Awaiting`), repeat; saves at step boundaries. A message sent mid-run (`Steer`) joins at the next step boundary (the UI queues it until then); a stop marks the reply `paused` and `Resume` carries on from it. App specifics come through the `RunHost` trait. Tests drive it with a scripted fake host.
  - `agent/ui.rs`: threads are kept as the UI's own message JSON (AI SDK `UIMessage`). Runs change them only through `Op`s, which the UI applies identically (`applyOp` in `sessions.ts`); also `to_core` (UI messages → provider `Message`s), the step builder (`ChatEvent`s → parts), citations and titles.
  - `workspace/`: Cowork's file and shell tools. All file access goes through a `cap_std::fs::Dir` on the granted folder, so `..`, absolute paths and escaping symlinks fail; `.git` and `.sush` are read-only; secret-looking files (`.env`, keys) need approval to read. `tools.rs` holds the tool specs, the per-call approval rule (shell always asks; edits ask unless the workspace is set to `auto-edits`) and the dispatcher, which checkpoints a file before changing it. `shell.rs` runs PowerShell on Windows and `sh` elsewhere with credential env vars removed, capped output, a timeout, and tree-kill on Stop.
    - `sandbox/`: commands run in an OS sandbox that confines writes to the workspace and a private temp folder (never `.git`): Seatbelt on macOS, bubblewrap on Linux (both also block the network), and on Windows a write-restricted token whose capability SID is granted (by ACL) the workspace folder, inside a Job Object; Windows can't block the network without admin. A self-test probe must pass before the sandbox counts as available (`SandboxStatus`). Shell commands run without asking only when the sandbox is available, blocks the network, the command doesn't request `network`/`unsandboxed`, and the workspace is set to edit automatically; otherwise they ask.
  - A provider is *wire format × endpoint × credential*. Only two wire formats exist (`OpenaiChat`, `AnthropicMessages` in `providers/`); Azure, OpenRouter, Groq, Ollama, etc. are just `ProviderConfig` presets (`provider.rs::presets`). A new endpoint speaking an existing format needs config, not code.
  - Each format implements an I/O-free `Decoder` that turns SSE events into normalised `ChatEvent`s. Dropping the returned stream aborts the HTTP request; that is the cancellation mechanism.
- **`apps/desktop/src-tauri`** (crate `sush`): thin shell exposing core to the UI as Tauri commands (registered in `lib.rs`). `AppState` (`state.rs`) holds providers (persisted to `providers.json` in the app config dir), the store, memory, live runs, and cancellation tokens for one-shot streams and sign-ins. `runs.rs` is the session manager: one live run per thread, every run's frames on one channel (`runs_subscribe`, which also returns live runs so a reloaded page catches up), connector tools called from Rust, UI-owned tools requested with a `client-tool` frame and answered with `tool_result`. For a Cowork session (`ThreadMeta.workspace_id`), `runs.rs` adds the workspace tools itself (any the UI sends are dropped), decides each call's approval (`RunHost::approval`), and records checkpoints for undo. `browser.rs` is Cowork's built-in browser: one native child webview (needs tauri's `unstable` feature) laid over the panel at the bounds the UI reports, driven by the `sush_core::browser` tools through `eval_with_callback`; pages get no IPC, and the app's own origins are refused. `workspaces.rs` adds workspaces through a folder dialog opened in Rust (the webview never names a path), and serves the file tree, file viewer and editor (`workspace_read_file`, `workspace_find`, `workspace_write_file` for the user's own saves, `workspace_reveal`), `sandbox_status`, `turn_diff` (each file a turn changed, before and after, from its checkpoints) and `undo_turn` (a whole turn, or one file). `terminal.rs` is the side panel's terminal: the user's own shell (PowerShell on Windows) in the workspace over plain pipes, not a PTY, and not sandboxed. Each command is wrapped so a marker line carrying the shell's cwd follows it (the UI's prompt); Stop kills the shell's tree and restarts it in that cwd. Likewise `pick_folder_attachment` and `save_text_file_as` open their dialogs in Rust. API keys and connector tokens go to the OS keyring (`secrets.rs`), never to disk or the webview. Debug builds instead keep them in an owner-only `dev-secrets.json` in the app config dir, because each `tauri dev` rebuild is re-signed and macOS would otherwise ask for the keychain password on every launch. `windows.rs` is the browser-style tab tear-off: `tab_drop` moves a tab dragged out of the strip into another window's strip (by cursor position) or into a new `session-*` window running the same page, and `tab_hover` has the strip under the cursor open a slot for it during the drag; each window subscribes to runs (frames go to all of them; `client-tool` frames only to the leader, `main` while it's open) and the browser webview moves to whichever window shows its pane. `whisper.rs` runs local dictation in-process (model downloaded on first use). `auth_server.rs` is release-only (`#[cfg(not(debug_assertions))]`): it launches the bundled auth server sidecar on port 47321. In dev you run `dev:server` yourself.
- **`apps/desktop/src`**: React 19 + Vite + Tailwind 4 + shadcn (`components/ui`) + AI SDK UI (`useChat`). Path alias `@/` → `src/`.
  - `lib/tauri.ts`: typed `invoke` bindings. Its types mirror sush-core's serde shapes (camelCase fields, kebab-case enum tags). **If you change a Rust command or serde type, update this file to match.**
  - `lib/transport.ts`: the chat message types (`SushUIMessage`) and `storeAttachments`. `chat_stream` remains only for one-shot calls (`lib/complete.ts`: titles, memory revision).
  - `lib/agent.ts`: what each request carries (system prompt, tool specs via `buildContext`), each tool's approval policy (`runTools`), and `runTool` for the tools the UI owns (`memory_*`, `chats_search`/`chat_read`, `skill`, `artifact_write`). `ask_user` and `skill_save` are answered in their cards; tools named `<connector>__<tool>` run in Rust after approval unless allowed.
  - Conversations and memory are stored on disk by Rust and loaded once at startup (`initStore` / `initMemory`, awaited in `main.tsx`). `lib/store.ts` and `lib/memory.ts` keep an in-memory copy for synchronous reads and write every change through to Rust in order. Keep UI code going through those modules' APIs. Conversations live in `sush.db` (`sush_core::store`: SQLite + FTS5 for `chats_search`); images and PDFs are content-addressed files in `blobs/`, served to the webview on the `sushblob` scheme and resolved to base64 in `chat_stream`; memory files are markdown in `memory/` (`sush_core::memory`), all under the app data dir. The library (`library.ts`: skills, design systems, connectors, plugins) and preferences still use localStorage via `createStore`.
  - `lib/workspaces.ts`: the workspace list, `CurrentWorkspace` (context for tool cards), file-change versions from `files-changed` frames, and undo. `components/workspace-panel.tsx` holds the header's folder chip (mode, sandbox status) and panel toggles, and the side panel: lazy file tree with a filter and context menus, tabs, the editable viewer (`components/code-editor.tsx`: a transparent textarea over shiki output, unsaved text in the drafts store in `workspaces.ts`, Ctrl+S saves), and the terminal (`components/terminal-pane.tsx`, no terminal emulator, drawn with the parts exported from `components/ui/Terminal.tsx`) below a draggable split. Under each Cowork turn, `components/file-changes.tsx` lists the files it changed with +/− counts, a diff and per-file Undo. The Chat / Cowork toggle in the sidebar's title bar switches the open session's kind (Cowork reopens the most recently used folder), and "New" starts the same kind as the open one. A new session's composer has `components/session-options.tsx` above it (switch folder or plain chat while the session is untouched; in a git repo, a branch chip that switches branches via `workspace/git.rs` and a "worktree" checkbox: on the first send, `worktree_create` adds a worktree on a new `sush/…` branch under the app data dir as its own workspace and the session moves into it) and the mascot, Sushi (`components/mascot.tsx`), standing on it. Cowork tool calls render in `WorkspacePart` (`tool-parts.tsx`); finished tool calls and the thinking between them collapse into one line (`components/activity-group.tsx`).
  - Sessions can be renamed, forked, filed under a project (`lib/projects.ts`: name + instructions in localStorage; membership is `ThreadMeta.project_id`) via `components/session-actions.tsx`. Incognito chats (`ThreadMeta.incognito`) are never stored: `Store::save_thread` skips them, `runs.rs` keeps their messages in memory until `thread_delete`, they get no memory/past-chat tools and no workspace, and `App.tsx` deletes one when you leave it.
  - Several windows: each keeps its own in-memory copy of the store, so `lib/windows.ts` broadcasts changes between them (conversations, memory, the workspace list), persisted `createStore`s follow other windows' writes via the `storage` event (pass `follow = false` for per-window state like the tab strip and Cowork panels), and `whenLeader` runs once-only work (automations). New code that changes shared state in memory needs to broadcast it too.
  - `lib/sessions.ts`: starts, answers (`respond`) and stops runs, builds each run's `RunConfig` (including `/skill` and `@connector` expansions), and mirrors every thread's messages from the run frames. `ChatView` reads a thread with `useThread`; there is no `useChat`.
- **`apps/server`**: Bun + Hono + better-auth (SQLite, migrated on startup). Email/password accounts. The webview is cross-origin, so auth uses the bearer plugin (`set-auth-token` header → localStorage → `Authorization: Bearer`, see `src/lib/auth.ts`) instead of cookies. In release builds it is compiled with `bun build --compile` into `src-tauri/binaries/sush-auth-<target-triple>` and shipped as a Tauri sidecar.

`apps/chat-ui.ts` is a standalone component file outside every workspace package; nothing imports it.

Project skills in `.claude/skills/` cover the common multi-file workflows: `check`, `ship`, `run-app`, `add-tauri-command`, `add-agent-tool`, `add-provider`, `release`.

## Gotchas

- Don't build, test, or typecheck after making changes (no `bun run typecheck`, `bun --filter desktop build`, `cargo build/check/test`, `tauri build`). Builds run only when the user asks, once a feature is complete and right before pushing: that's the `/ship` skill (or `/check` to verify without pushing).
- The CSP in `tauri.conf.json` (and `tauri.release.conf.json` for release) restricts `connect-src`. If you point `VITE_AUTH_URL` at a new origin, or the webview needs to reach a new host, add it there.
- Server env: `BETTER_AUTH_SECRET` (required in production), `BETTER_AUTH_URL`, `PORT`, `DATABASE_PATH`.
