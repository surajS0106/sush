# Voice Mode — Design Notes

Last updated: 2026-11-19

## What changed

### 2026-11-19 (user placeholders)
- `VoiceEvent::SpeechStopped` now carries the `item_id` the server will transcribe the user's words into (`crates/sush-core/src/voice/mod.rs`, `realtime.rs`, mirrored in `lib/tauri.ts`). The placeholder bubble created on speech-stopped uses that id, so its transcript fills it directly (`lib/voice-session.ts`). Matching placeholders in order remains only for a server that sends no id.
- A placeholder is removed when its transcription comes back empty, or after 10 seconds without words (`dropIfEmpty`, `PLACEHOLDER_MS`).
- When an answer starts, every empty placeholder except the latest is dropped (`ensureAssistant`), and words that arrive with no placeholder left are put before an answer still in progress rather than after it. The call is saved to the chat in this order, so the stored turns alternate correctly.
- No placeholder is added on speech-stopped when the last line is already the user's: xAI streams the user's words into a line of their own while they talk, so a placeholder below it only flashed dots for a moment. The "being heard" dots follow the same rule (`Lines` in `components/voice-mode.tsx`).
- Cutting in trims each answer to the words that were heard (`trimToHeard` in `lib/voice-session.ts`, used by `cutRealtime` and `cutTurn` before the player stops). It applies to any answer not fully heard, including one already marked final: xAI finishes sending an answer well before its audio ends. The trimmed text is what the chat keeps and what the model is given as context afterwards, matching the server-side truncation of its audio.
- Cutting in is detected on this computer by `BargeIn` (`lib/voice-audio.ts`), for realtime and turn-by-turn calls alike, alongside the server's own detection. It compares the mic with what is playing (`Player.outputRms`): it learns how much of the answer leaks back into the mic, the lowest mic-to-output ratio seen while it plays, and counts the user as talking when the mic is well above that leak for two chunks (about 170 ms). It reads the mic's level before the whisper boost (`openMic` passes `raw`), since the boost lifts the echo too. It replaced a loudness-only `TurnDetector`, which needed about 340 ms above a fixed threshold and missed a short "stop".
- Audio that arrives for an answer after it was cut is dropped (`onRealtime`'s `audio` case checks the line's `cut`). The server goes on streaming for a moment after `response.cancel`, and those chunks used to be queued and played, so the voice carried on after the text had stopped.
- "Pick up whispers" (Settings → Voice mode, on by default; `VoiceModeSettings.whispers`): `openMic` runs each chunk through `QuietBoost` (`lib/voice-audio.ts`) before anything listens to it. It tracks the room's background level, lifts only chunks that stand above it toward an ordinary speaking level (up to 6×), leaves loud speech alone, and rounds off peaks with `tanh` instead of clipping. The server's detector, the local detectors and the transcriber all get the lifted audio.

### 2026-11-19 (voice inside the chat, SVG orb)
- Voice mode no longer opens a full-window overlay. `VoiceDock` (`components/voice-mode.tsx`) takes the composer's place in the chat's dock while a call is on (`voiceOn` in `components/chat-view.tsx`), and `VoiceLines` renders the call's lines after the thread's messages with the chat's own `Message` components. The call is shared between the two through a small module store (`useLiveCall`). When the call ends, the lines are cleared and its turns are saved as the chat's messages. A call started from an empty chat uses the transcript layout. The composer no longer mounts voice mode itself.
- The dock is the orb floating above a pill bar: status, provider and voice, mute, voice settings and end. A failed call shows its error and Try again in the bar; with no key, the bar offers "Add a key".
- `GlassOrb` is now drawn in SVG (`Sphere` in `components/glass-orb.tsx`): a body running from a rich top hue to a bottom hue, a milky centre, a rim that darkens and splits into warm (top right) and cool (left) light, a refraction line inside the left edge, a crescent of light top left and one bottom right, small glints, a coloured shadow, and a mirrored, fading copy below as a reflection. Two soft blobs of colour drift inside, faster while thinking. Hues come from ten hand-picked pairs (`PALETTES`) instead of any two hues, so no voice gets a muddy pair.

### 2026-11-19 (call layout and glass orbs)
- The call screen is laid out like a chat (`components/voice-mode.tsx`): the live transcript fills the page, with the user's words in bubbles on the right and the answer on the left as it is heard; below it the orb floats above a pill bar holding the status, mute and end. The caption view and its T toggle are gone. While the user is talking and no line exists yet, a bubble with dots shows they're being heard.
- Added `GlassOrb` (`components/glass-orb.tsx`): a glass bubble with two hues blending top to bottom, a bright rim with coloured edges, highlights and an optional reflection. `orbHues(seed)` derives the hues from the voice id, so each voice has its own colours. It floats (`orb-float` / `orb-reflect` in `index.css`, off with reduced motion), and its colour turns fast while thinking.
- The voice picker in Settings → Voice mode shows each voice's orb (`VoiceAvatar` in `components/voice-section.tsx`), floating while that voice's preview plays. The call's background is tinted with the voice's hue.

### 2026-11-19
- xAI's "Cancellation failed: no active response found" no longer shows mid-call. `parse` in `crates/sush-core/src/voice/realtime.rs` also treats an error as soft when the `soft-` event id is at the top level of the event, or when the message says there is no active response or already one active. xAI sends neither OpenAI's error code nor the event id inside `error`. Tests cover both shapes.
- Overlay (`components/voice-mode.tsx`): the orb's glow is a radial gradient instead of a blurred disc, the swirl is blurred so the conic gradient has no seam at the centre, and the mute button is a soft filled circle instead of an outlined one.
- Captions and the transcript follow the voice on realtime providers. `Player.progress()` (`lib/voice-audio.ts`) reports how much of the playing answer has been heard and how much audio has arrived, and `VoiceConversation.visibleText` (`lib/voice-session.ts`) shows the answer's text up to the smaller of its share of the audio heard and 17 characters a second, cut at a word. Words that arrive before any of their audio stay hidden. On turn-by-turn providers each sentence appears when its audio starts: `Player.pushEncoded` now resolves with the sentence's start time, kept as cues per answer. The caption and transcript re-render every 100 ms while an answer plays (`useTicking` in `components/voice-mode.tsx`). The full text is still what the chat keeps.
- Mid-call errors show as a neutral pill with an amber dot at the bottom of the overlay (`Notice`), and fade after six seconds. They used to be red text that stayed until the next error.

## Why

The user asked for ChatGPT-style hands-free voice where the user picks the provider and pays with their own key. OpenAI and xAI have true speech-to-speech models that use the same event protocol, so one parser serves both. Sarvam and ElevenLabs offer speech-to-text and text-to-speech rather than a single realtime model, so they run listen → transcribe → think → speak. Sarvam can think with its own `sarvam-105b`, or the user can switch it to the chat's model. ElevenLabs always uses the chat's model.

Keys never reach the webview (CLAUDE.md: keys go to the keyring), so the realtime socket lives in Rust. The cost is one IPC call per ~85 ms mic chunk, which is small. The same rule is why previews return base64 audio that is decoded with `decodeAudioData`: no CSP change is needed for media hosts or `data:` URLs.

xAI had five voices, which left an empty slot in the voice grid at both two and three columns. Carina is one of the 21 voices xAI added in July 2026. Its announcement names it as a support voice but gives no id or gender, so `carina` follows the lowercase naming of the other xAI ids, and the gender and description are provisional until the voice has been heard. Naksh and Atlas were added the same way, after the user asked for Indian and Australian accents. Naksh is a Hindi name, so it is the likeliest Indian voice. None of the published names points to an Australian accent, so Atlas is a stand-in to be swapped for another new voice if it doesn't sound Australian. Loading xAI's list from `GET /v1/tts/voices`, as ElevenLabs voices are loaded, was the alternative; it was deferred because the response shape couldn't be checked.

Placeholders used to be filled oldest first. When the server counted noise or the answer's own echo as speech and never transcribed it, every later transcript landed one placeholder too early: the user's latest words appeared above older turns, and the empty bubbles showed dots for the rest of the call. Keying each placeholder by its item id removes the guesswork; the timeout covers stops that are never transcribed at all.

Whispers were missed because every listener is tuned for a speaking voice: the server's VAD, our loudness thresholds, and the browser's noise suppression, which treats breathy speech much like hiss. Lowering each threshold separately would have meant three tunings and more false starts. Lifting quiet speech once, at the mic, fixes all of them together, and gating the lift on the room's own level keeps silence from turning into noise. The trade-off is that a noisy room can now cut in more easily, which is why it is a setting.

Voice moved into the chat because a call is part of the conversation, as in ChatGPT: the earlier messages stay in view, the call's words appear among them, and closing the call leaves the user where they were. Rendering live lines separately from the stored thread keeps the store free of half-heard text; the cost is a swap from live lines to saved messages when the call ends, which look the same. The orb was redrawn in SVG after the CSS version read as a flat ball next to the reference image: radial gradients, masks and blur filters can place the rim colour, crescents and refraction line where real glass puts them, and the same drawing scales from 36 px to 88 px.

The layout follows ChatGPT's voice mode, which the user pointed to: a running transcript reads better than one caption, and keeps the earlier turns in view. The orb moved to the bottom so the transcript has the page. Giving each voice its own orb colours ties the call to the voice picked in Settings, where the same orb sits next to its name. The orb is built from layered CSS gradients and shadows instead of an image or WebGL, so it costs nothing to load, scales from 36 px in the picker to 96 px in a call, and still swells with loudness every frame.

OpenAI and xAI stream an answer's transcript faster than its audio, so the caption showed whole sentences before they were spoken. There are no word timings in the realtime protocol, so the reveal is estimated: the share of audio heard, capped by a brisk speaking pace so it never runs ahead. It can lag slightly behind a fast speaker, and the rest appears when the audio finishes. Turn-by-turn providers stream the model's text as it is written, which also ran ahead; there the audio comes a sentence at a time, so each sentence can be shown exactly when it starts.

The cancel error appeared when the user tapped the orb or spoke while nothing was playing. It is harmless, and the call carries on, but red text under the orb read as a failure. Matching on the message text is looser than matching a code, so it is limited to the two "active response" cases. The glow was clipped into a faint rectangle by its blur filter, and the swirl's conic gradient met in a visible point. A mid-call notice doesn't end the call, so it is styled as information rather than an error and leaves by itself; errors that end the call keep the red message with Try again.

The key entry was reworked after review. Cards could be left open with an empty field next to closed ones, the "Get a key" link disappeared as soon as the field opened (the moment a user without a key needs it), and a second row of Cancel and Get a key competed with the field. Moving the link into the header keeps the path to a key visible without adding a row. Save is hidden until there is something to save, so a faded Save button doesn't sit in every open card. The trade-off is that the row's layout shifts slightly when Save appears.

Voice turns are saved into the open chat when the call ends, so the chat continues from them in text. The voice model is given the chat so far as text in its instructions rather than as replayed items. This is because OpenAI and xAI accept different item shapes, and instructions work the same on both.

## What makes it stand out

- Interrupting is exact on realtime providers. `Player.stop()` reports how many milliseconds of the answer were heard, and `conversation.item.truncate` cuts the model's memory of the answer to that point. A naive client keeps the unheard text in the model's context.
- Server errors about best-effort events (a cancel when nothing is playing) are tagged with a `soft-` event id and hidden, so harmless races don't produce error messages.
- On turn-by-turn providers, answers are spoken sentence by sentence while the model is still streaming. Each sentence's audio is fetched as soon as the sentence is complete and played in order, so the first words arrive before the answer is finished.
- The turn detector tracks the room's noise floor. While the model is speaking it needs a louder and longer burst before it counts as the user talking, so the model's own voice leaking into the mic doesn't interrupt it. This is on top of the browser's echo cancellation.
- Voices carry a gender (from ElevenLabs' `labels.gender`, otherwise built-in metadata), so the grid can be filtered by female, male or neutral, and each voice can be previewed through that provider's own text-to-speech.
- With Sarvam, the language the transcriber detects is passed to Bulbul as the speaking language (`sarvam_language`), so a reply in Hindi or Tamil is spoken in that language rather than in an English voice.
